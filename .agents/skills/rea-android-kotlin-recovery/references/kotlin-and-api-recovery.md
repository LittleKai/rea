## 1. Why R8/ProGuard Leaves Kotlin Metadata Intact

Even when R8 or ProGuard renames packages and classes to short identifiers (`a.b.c`), the Kotlin compiler embeds two annotations that often survive shrinking because reflection, serialization, and coroutine stack traces depend on them:

1. **`@kotlin.Metadata` (`d2` array):**
   - The first element of `d2` in a class-level `@Metadata` annotation stores the internal JVM descriptor of the original Kotlin class (`"Lcom/vendor/feature/Signer;"`).
   - Subsequent entries in `d2` contain original property names, function names, and parameter names.
2. **`@kotlin.coroutines.jvm.internal.DebugMetadata`:**
   - Every suspend lambda or state machine generated by `kotlinc` carries `c = "<original_class_fqn>"`, `f = "<original_source_file>.kt"`, `l = {<line_numbers>}`, and `m = "<original_method_name>"`.

## 2. Step-by-Step Workflow with `scripts/kotlin_apk_inspector.py`

### Step 1: Container & Framework Triage (`fingerprint`)

Before decompiling an unknown `.apk` or `.xapk`, run:

```powershell
D:\Dev\conda-envs\py312\python.exe -X utf8 -I -B scripts/kotlin_apk_inspector.py fingerprint <apk_or_xapk> --json
```

- Check `primary_framework` (`flutter`, `react_native`, `unity`, `xamarin`, `cordova_capacitor`, `kotlin`, or `native_android`).
- Check `has_kotlin_metadata`: when `true`, running `recover-kotlin` on JADX output will recover original class and package hierarchies.
- Check `split_apks` and `abis` to locate native `.so` libraries for REA native binary analysis.

### Step 2: Recover Obfuscated Kotlin Names (`recover-kotlin`)

After decompiling the APK with JADX into `<jadx_out>/sources`, run:

```powershell
D:\Dev\conda-envs\py312\python.exe -X utf8 -I -B scripts/kotlin_apk_inspector.py recover-kotlin <jadx_out>/sources <out_dir>
```

This generates three artifacts in `<out_dir>`:

- `mapping.tsv`: Tab-separated `obf_fqn`, `real_fqn`, and relative `.java` path.
- `mapping.json`: Dictionary mapping `{obf_fqn: real_fqn}`.
- `packages.txt`: Ranked histogram of original Kotlin packages so you can immediately spot authentication, billing, crypto, or network modules.

### Step 3: Navigate and Grep with Deobfuscated Context (`lookup`)

- **Translate a single obfuscated class:**
  `lookup <out_dir> -o a.b.c`
- **List all classes in an original package:**
  `lookup <out_dir> -p com.vendor.network`
- **Regex search across JADX sources with automatic `real_fqn` labels:**
  `lookup <out_dir> --grep "CertificatePinner|HmacSHA256" --sources <jadx_out>/sources`

### Step 4: Extract Network & API Layer (`find-api`)

Run `find-api` to locate HTTP route definitions, interceptors, and pinning configurations:

```powershell
D:\Dev\conda-envs\py312\python.exe -X utf8 -I -B scripts/kotlin_apk_inspector.py find-api <jadx_out>/sources --all --json
```

- **`retrofit`:** Extracts `@GET`, `@POST`, `@PUT`, `@DELETE`, `@PATCH`, `@HEAD`, `@OPTIONS`, `@HTTP`, and `.baseUrl(...)` call sites.
- **`okhttp`:** Extracts `Request.Builder`, `HttpUrl.parse`, `addHeader`, `addInterceptor`, and `CertificatePinner` usages.
- **`ktor`:** Extracts `io.ktor` and `HttpClient` usages.
- **`urls`:** Extracts hardcoded HTTP/HTTPS and WS/WSS endpoint strings.
